# 47 — UX & Feature Map

_Generated 2026-08-06 by a parallel multi-agent audit (10 domain readers) that inventoried every editor feature against Microsoft Excel and Google Sheets. Companion docs: [48 — Feature Pipeline](48-FEATURE-PIPELINE.md), [49 — Design System](49-DESIGN-SYSTEM.md)._

> Each feature was read against the actual source, not the trackers. UX grade is vs. Excel/Sheets: ★★★★ excellent · ★★★ good · ★★ fair · ★ poor.

## Navigation & viewport

| Feature | Status | UX | Parity gap vs Excel/Sheets | Top UX issues | Recommendation |
|---|---|---|---|---|---|
| **Scrolling smoothness (mouse-wheel / trackpad, fluid pixel scroll)** | ✅ Done | ★★★ | Excel/Sheets both map Shift+wheel to horizontal scroll and give inertial/momentum feel on trackpads; here horizontal scroll only happens if the device emits deltaX (no Shift+wheel fallback), and there is no momentum, no smooth-animated scroll for keyboard/go-to jumps (they snap). Sheets also shows a row/column tooltip while scrolling. | draw() runs fully synchronously inside the wheel handler with no requestAnimationFrame coalescing — every wheel tick re-calls measure() which does session_cells + several JSON.parse round-trips into WASM, so rapid wheel/trackpad input can drop frames on large or heavily-styled sheets (contradicts the 60fps target); No Shift+wheel -> horizontal mapping: users on a plain wheel mouse cannot scroll horizontally except via the H scrollbar thumb; No momentum/inertia or eased deceleration; scroll stops dead when input stops, feeling less fluid than Sheets/Excel-web | Coalesce redraws through a single requestAnimationFrame (accumulate wheel deltas, draw once per frame) and cache the last measure() when only scroll changed; add a Shift+wheel -> deltaX fallback; consider light inertial smoothing and an optional animated ensureVisible for large jumps. |
| **Custom (OS-consistent) scrollbars** | ✅ Done | ★★★ | Excel/Sheets scrollbars support click-in-track to page up/down, end arrows/steppers, and a proportional thumb tied to the true sheet extent; this thumb is drag-only and its size is computed from used-bounds+buffer (contentH = max(usedExtent, scrollY+viewH+1)), so the thumb rescales/creeps as you scroll past the data instead of representing a stable extent. | Clicking the scrollbar track does nothing — no page-scroll toward the click (a basic scrollbar affordance in every reference product); Thumb size jitters: because contentH/contentW grow with the current scroll offset, the thumb shrinks as you scroll into empty space, so its position is not a faithful map of where you are; No step arrows and no scroll-position tooltip (Excel shows 'Row 128' while dragging) | Add track-click paging and (optionally) end steppers; base the extent on a stable large virtual size (or the sheet max) so the thumb doesn't rescale while scrolling; add a drag tooltip showing the target row/col; give the thumb a role=scrollbar + aria-valuenow and arrow-key support. |
| **Freeze panes** | ✅ Done | ★★★ | Only menu-driven (freeze top row / first col / up-to-selection / unfreeze). Excel and Sheets also let you drag the freeze divider directly, keep the current scroll position when freezing, and Excel additionally offers Split panes (independent scroll regions without pinning). Setting freeze here resets scrollX/scrollY to 0. | setFreeze() force-resets scroll to (0,0) on every freeze change (editor.js:1019), so freezing mid-sheet snaps the viewport back to A1 — Excel/Sheets keep your position; No draggable freeze affordance (the Sheets grey drag-bar / Excel divider drag); discoverability rests entirely on the toolbar menu; Divider is a single muted 1px line; reference products use a heavier line/shadow so the frozen boundary reads clearly, especially in dark mode | Stop zeroing scroll on freeze (clamp instead so the frozen region shows rows 0..fr and the body keeps its offset); add a draggable divider handle to set/adjust freeze by dragging; thicken/shadow the divider. Split panes can stay backlogged. |
| **Keyboard navigation (arrows, Enter/Tab, Ctrl+Arrow, Home/End, PgUp/PgDn)** | 🟡 Partial | ★★★ | Missing plain End (Excel 'End mode' / Sheets 'jump to last cell with data in the row'); no Alt+PgUp/PgDn (page left/right); Tab does not wrap within a selected range and Enter does not return to the entry's starting column after a Tab run (Excel behavior); no Ctrl+Backspace (scroll back to active cell). | Plain End key is unhandled — only Ctrl+End works; users expecting End-then-Arrow or End=row-end get nothing; PageUp/PageDown only page vertically; no horizontal paging (Alt+PgUp/PgDn); Tab always moves one cell right and never wraps inside a multi-cell selection, and Enter after Tabbing across a row doesn't carriage-return to the start column — data-entry ergonomics fall short of Excel | Add End (row-end / end-mode), Alt+PgUp/PgDn horizontal paging, Tab-wrap + Enter-return within an active selection, and Ctrl+Backspace. Cache used-bounds in the session so session_edge is O(1)-ish instead of a full scan per keypress. |
| **Go-to / Name box (jump to cell/range, named ranges)** | ⬜ Missing | — | The 'cell-ref' element is a read-only <span> (editor.html:231; only written via cellRef.textContent at editor.js:734). There is no editable Name box, no Ctrl+G / F5 Go-To, no way to type A1/A1:C5 or a named range to jump/select, and no 'nR x nC' size readout while dragging a selection. Every reference product ships an editable name box. | Cannot navigate to a distant cell by address at all — must scroll or Ctrl+Arrow there; No range-size feedback (Excel/Sheets show '3R x 2C' in the name box during a drag); No named-range awareness in the UI even though defined names exist in the model/import path | Turn cell-ref into an <input> Name box: Enter parses an A1 cell/range (and defined name) and selects+scrolls to it; show live 'nR x nC' during drag-select; add Ctrl+G/F5 to focus it. This is the single highest-value missing navigation feature. |
| **Zoom (view scale)** | ⬜ Missing | — | No zoom whatsoever — no Ctrl+wheel zoom, no zoom control/percent in the status bar, no View>Zoom. COL_W/ROW_H come straight from engine defaults and cellPx() is fixed (editor.js:130); devicePixelRatio is used only for canvas crispness, not user zoom. Excel/Sheets both offer 50-200%+ zoom and Ctrl+wheel. | No way to shrink to see more of the sheet or enlarge for readability; Ctrl+wheel currently falls through to normal scroll instead of zooming (a surprise vs. every competitor); Zoom level is not persisted per sheet (xlsx sheetView zoomScale is ignored on import/export) | Introduce a viewport zoom factor applied to the canvas transform and to px<->cell math (multiply COL_W/ROW_H/offsets and font sizes), wire Ctrl+wheel and a status-bar zoom control, and round-trip sheetView zoomScale. |
| **Gridline toggle (show/hide gridlines)** | ⬜ Missing | — | Gridlines are always drawn (editor.js:442-461) with no View toggle to hide them, and the sheet's showGridLines flag is neither modeled nor read from/written to xlsx sheetView. Excel/Sheets both toggle gridlines and persist the setting. | No user control to hide gridlines for a cleaner/report look; Imported workbooks that hid gridlines will still render them (fidelity gap) | Add a Sheet.view.show_gridlines flag (default true), import/export sheetView showGridLines, a View toggle in the UI, and gate the gridline stroke loop on it. |
| **R1C1 reference style** | ⬜ Missing | — | Headers, the cell-ref readout, and all formula rendering are A1-only (colName() at editor.js:73-82); there is no R1C1 toggle and the formula engine explicitly defers R1C1 parsing. Excel offers an R1C1 reference-style option. | No reference-style switch anywhere in the UI; Formula layer would need R1C1 parse/format support before the editor could offer it, so this is a cross-layer gap not just a UI toggle | Low priority (advanced/niche). When scheduled: add R1C1 support in the formula crate (parse + display), then a workbook-level reference-style preference that flips headers, the name box, and formula-bar rendering. |

## Selection

| Feature | Status | UX | Parity gap vs Excel/Sheets | Top UX issues | Recommendation |
|---|---|---|---|---|---|
| **Single-cell selection (click / focus cell)** | ✅ Done | ★★★ | At parity for the basic gesture: click sets a 2px accent focus border, tint fill, and clicking a merged cell snaps to its top-left anchor. Missing the subtle Excel/Sheets touch where the focus cell inside a multi-cell selection is drawn white (un-tinted) to distinguish it from the extended range. | Focus cell is not visually distinguished from the rest of a range selection (Excel/Sheets paint the active cell white); only the outer border marks the range, so within a big selection you cannot see where the next-typed cell is.; No selection state is preserved across sheet switches — switchSheet()/resetView() (editor.js:1367,1375) always slams selection back to A1, whereas Excel remembers each sheet's selection.; Enter/Tab after selecting a range do not cycle within the selection (editor.js:1861,1864 just move down/right and collapse the range), unlike Excel/Sheets data-entry flow. | Paint the active cell background in bg color (un-tinted) inside multi-cell selections; persist per-sheet selection in state keyed by sheet index; make Enter/Tab wrap within the active range when it is multi-cell. |
| **Range selection (click-drag)** | ✅ Done | ★★★ | Drag-to-select a rectangle works with anchor/focus and live redraw. Gap vs Excel/Sheets: no live 'RxC' dimension readout during the drag (the name box keeps showing only the single focus cell), and the status bar Sum/Avg/Count only updates on drag end feel is fine but there is no marching-ants / crisp range outline animation. | No live selection-size feedback: during a drag Excel shows '3R x 4C' in the name box and Sheets shows it as a tooltip; here cellRef (editor.js:734) always shows just the focus A1, so users get no dimensional feedback.; Range outline is a static 2px rect; there is no distinct handling for very large selections and no marching-ants, so a selection can be hard to tell apart from a thick cell border.; Cannot shrink a selection by dragging back precisely across hidden/frozen boundaries in all cases — clamping to body (editor.js:1689-1690) is correct but interaction near the freeze divider is untested. | Show live 'NR x NC' in the name box (or a floating badge) while state.dragging and while extending with shift; consider a lightweight animated dashed outline for the active selection to separate it from cell borders. |
| **Whole row / whole column selection via header** | 🟡 Partial | ★★ | Single-click on a row/column header selects the whole line (selKind rows/cols), focus stays at the near edge so the view does not jump (UX-01), and header band tints. But the header path is click-only: it does NOT support shift-click to extend a row/column band, Ctrl/Cmd-click to add disjoint rows/columns to a multi-range, or click-drag across headers to select a contiguous block of rows/columns — all three are standard in Excel and Sheets. | No drag across headers: mousedown for a header returns immediately (editor.js:1657-1658) without setting state.dragging, so you cannot drag over rows 3-10 to select them — you must resize-window your expectations.; No shift-extend on headers: selectRow/selectColumn accept an `exp` flag (editor.js:950,958) but the click handler never passes it, so shift+click a second row header replaces instead of extending.; No Ctrl/Cmd multi-select of rows/columns: header clicks bypass the addRange() path entirely, so you cannot build 'rows 2, 5, 9' or 'cols A, C, E' the way every real sheet allows. | Route header mousedown through a header-drag state: set an anchor row/col, honor shiftKey (extend band via selectRow/Column with exp=true), honor meta/ctrlKey (bank current row/col range then start a new one), and on mousemove extend + auto-scroll. This is the single biggest Selection-domain gap. |
| **Whole-sheet selection (corner box / Ctrl+A)** | ✅ Done | ★★★ | Corner click and Ctrl+A set selKind 'all'; highlight and header tint span the whole viewport, and effectiveRange expands to used bounds for formatting/clipboard (UX-02). Gap: Ctrl+A always jumps straight to whole-sheet, whereas Excel/Sheets do progressive Ctrl+A (first the contiguous data region around the active cell, then the whole sheet on a second press). | No progressive Ctrl+A (data-region-then-all); a single press over a data island selects everything, which over-selects for most format/clear operations.; selKind 'all' anchors sel/anchor to firstRow/firstCol (editor.js:945-946), i.e. the current scroll position rather than A1, so a subsequent shift-arrow extends from a scroll-dependent origin — mildly surprising. | Implement two-stage Ctrl+A using session_used_bounds / a contiguous-region probe: first press selects the current data region, second selects all. Anchor whole-sheet selection to A1 for predictable subsequent extends. |
| **Multi-range selection (Ctrl/Cmd+click)** | 🟡 Partial | ★★ | Ctrl/Cmd+click banks the current rectangle and starts a fresh one; Ctrl+drag extends the new range; each range gets the tint; formatting, clear and Sum/Avg/Count fold across all ranges (UX-24). Gaps vs Excel/Sheets: (1) cannot deselect — Ctrl+clicking a cell already in the selection adds an overlapping 1x1 range instead of removing it; (2) no whole-row/column can be added to a multi-range (headers bypass addRange); (3) copy/paste of a multi-range is not supported the way Excel handles same-shape multi-area copy. | No toggle-off: Ctrl+click on an already-selected cell should remove it (Sheets/Excel behavior); here it always adds, so you cannot correct a mis-click without starting over.; Overlapping Ctrl+click ranges are double-counted in Sum/Count (acknowledged in code comment editor.js:751-752) — Excel also double-counts, so this is defensible, but combined with no-deselect it compounds mistakes.; Right-click hit-testing (editor.js:1784-1787) only checks the active selRect, not banked ranges — right-clicking inside a banked range but outside the active one collapses the whole multi-range to a single cell. | Add Ctrl+click toggle-off (if the click lands in an existing range, split/remove it); make right-click preserve the selection when the click is inside ANY range in allRanges(); extend addRange to accept row/column bands once header-drag lands. |
| **Name box (reference readout)** | 🟡 Partial | ★ | The name box is a display-only <span> that shows the focus cell A1 (e.g. 'B7'). In Excel/Sheets the name box is an editable input: you can type a reference or a defined name and press Enter to navigate/select, it shows 'RxC' during a drag, and it lists/creates named ranges. None of the interactive behavior exists — it is a read-only label. | Not editable: you cannot type 'C5' or 'A1:D10' to jump/select — a core spreadsheet affordance is entirely absent.; Shows only the single focus cell, never the range dimensions during selection nor the top-left of a range selection like Excel.; No named-range awareness (no defined names in the engine surfaced here), so the box can never show or accept a name. | Convert #cell-ref to an <input>: on Enter parse an A1 cell or range (reuse the engine's reference parser via a new session_parse_ref or client-side A1 parsing) and select/scroll to it via select()/extend()+ensureVisible; render 'NR x NC' while dragging; later back it with defined names. |
| **Go-to (F5 / Ctrl+G, go-to-special)** | ⬜ Missing | — | No Go-To dialog and no F5/Ctrl+G binding (keydown handler editor.js:1822-1872 has no F5/G). Excel and Sheets both offer navigate-to-reference and 'go to special' (constants, formulas, blanks, current region, etc.). Entirely absent. | No keyboard path to jump to an arbitrary cell/range other than scrolling or Ctrl+arrow edge-jumps.; No go-to-special (select all formulas / blanks / errors), which is a common power-user selection tool.; Combined with the non-editable name box, there is literally no type-a-reference navigation anywhere in the editor. | Ship the editable name box first (covers 90% of go-to need), then add a Ctrl+G modal for range entry; defer go-to-special until conditional formatting / error tooling exists to feed it. |
| **Extend selection with Shift (click + keyboard)** | ✅ Done | ★★★ | Shift+click and Shift+arrow both extend from the anchor with correct anchor/focus semantics and call ensureVisible so the view follows. At parity for cell selections. Minor gap: shift-extend does not apply to header (row/column) selections, and there is no Shift+Space / Ctrl+Space to select the current row/column of the active cell. | Shift+click while a whole row/column is selected silently converts to a cell selection (extend() forces selKind 'cells', editor.js:821) rather than extending the row/column band.; No Shift+Space (select row) / Ctrl+Space (select column) keyboard shortcuts, which Excel users expect.; Shift+PgUp/PgDn uses geo.rows (visible count) as the page size (editor.js:1866-1867) — correct in spirit but the page size drifts with variable row heights, so extension distance is slightly unpredictable. | Make extend() respect the current selKind so shift-extend grows a row/column band; add Shift+Space / Ctrl+Space to select the active row/column. |
| **Select-to-edge (Ctrl+Shift+Arrow, Ctrl+Home/End)** | ✅ Done | ★★★ | Ctrl+Shift+Arrow extends to the data-block edge via the engine's session_edge block-jump, and Ctrl+Home/Ctrl+End jump to A1 / used-bounds corner (UX-23). Matches Excel block-jump semantics well. | Ctrl+End targets used-bounds (b.rows-1,b.cols-1) which can differ from Excel's 'last used cell incl. formatting' definition; acceptable but may surprise on sheets with trailing formatted-but-empty cells.; No visual cue that a jump crossed a large gap (no smooth scroll); selection teleports, which is standard but abrupt. | Keep as-is; optionally align session_used_bounds with a formatting-aware last-cell so Ctrl+End matches Excel exactly. |
| **Select visible cells only (skip hidden)** | ⬜ Missing | — | No 'select visible cells only' (Excel Alt+;) — a selection over hidden rows/columns includes the hidden cells, and copy (session_copy_tsv editor.js:1247) copies them too. Excel/Sheets let you restrict operations to visible cells, which matters heavily with the filter feature (UX-42) that hides rows. | Copying a filtered range copies hidden rows as well (no visible-only mode), so copy/paste after filtering silently includes filtered-out data — a data-integrity surprise.; No keyboard or menu affordance for visible-only selection. | Given the existing row-filter, add a 'visible cells only' copy path (have the engine skip hidden rows/cols in session_copy_tsv, or add a session_copy_visible), and optionally an Alt+; selection modifier; prioritize the copy behavior since it is a correctness issue with filtering. |
| **Drag auto-scroll (edge-pan while selecting)** | 🟡 Partial | ★★★ | For cell range-drag, dragging into the 28px edge band pans the body on rAF and keeps extending the selection, speed proportional to overshoot, freeze-aware — good, matches Excel feel. Gap: auto-scroll is ONLY wired to state.dragging (cell selection). It does NOT engage during drag-fill (updateFill editor.js:1590), during formula reference-drag (editor.js:1674-1683), or during header selection (which has no drag at all), so none of those can extend past the visible window. | Drag-fill cannot extend beyond the viewport: updateFill (editor.js:1590) never calls maybeAutoScroll, so you cannot fill a series down past the visible rows in one gesture.; Formula reference-drag (selecting A2:A400 while typing a formula) also does not auto-scroll, capping range picking at the visible window.; Header row/column selection has no drag and thus no auto-scroll (compounds the header-drag gap). | Factor the edge-pan loop so it can drive any active drag (cell, fill, ref, header) — pass a callback that maps the clamped pointer to the drag's own extend logic; clamp/ease the max scroll speed. Enabling it for drag-fill and ref-drag is the highest-value fix. |

## Editing & clipboard

| Feature | Status | UX | Parity gap vs Excel/Sheets | Top UX issues | Recommendation |
|---|---|---|---|---|---|
| **Inline (in-cell) edit** | ✅ Done | ★★★ | No Alt+Enter multi-line entry (Enter always commits); the editor box is fixed to the cell size and does not grow for long text; no in-formula reference color-coding of the tokens being typed. | No Alt+Enter to insert a newline inside a cell — Enter unconditionally commits, so multi-line cell content cannot be typed (only pasted/round-tripped); Editor is a plain single-line input clamped to the cell width/height; long values scroll invisibly inside a tiny box instead of expanding like Excel/Sheets; No colored highlighting of referenced ranges while editing a formula (Excel/Sheets outline each ref in a matching color) | Add Alt+Enter -> insert \n and switch the inline editor to a multi-line, auto-growing overlay; add reference token colorization shared with the formula bar; wire Shift+Enter/Enter-after-Tab navigation to match Excel's entry box. |
| **Formula bar** | 🟡 Partial | ★★ | The formula bar is a disconnected single-line input: no function autocomplete, no click-to-insert cell references, no live validation, no fx/insert-function button, no expand toggle, and the cell-reference readout is a non-editable <span> so there is no Name Box / Go-To navigation. | Name box (#cell-ref) is a display-only <span> — you cannot type an address or a named range to jump there (no Go-To); this is a core navigation gap that lives in the formula-bar chrome; Formula editing UX (autocomplete, click/drag reference insertion) is wired only to the inline editor's input event (editor.js:1874) — typing a formula in the formula bar gets none of it; Formula bar keydown only handles Enter (editor.js:1887): no Escape-to-cancel, no Tab, no arrow behavior, and Enter commits without advancing the selection | Make the name box an editable input that parses A1/range/named-range and navigates; factor the inline editor's autocomplete + ref-insertion + validation into a shared controller and bind it to the formula bar too; add an expand toggle and fx button. |
| **Copy / paste (values, formats, formulas)** | 🟡 Partial | ★ | Copy serializes only DISPLAY TEXT to the OS clipboard (session_copy_tsv calls display_text). Formulas and ALL formatting are lost on copy/paste: a formula copies as its computed value, and paste re-parses each field as fresh input. There is no internal rich clipboard, no HTML/format payload, and no relative-reference shifting on paste. | Copying a formula and pasting it yields the value, not the formula — the single most important spreadsheet clipboard behavior is missing (=B2*C2 pastes as e.g. 13.5); No formatting travels with copy/paste — bold, fill, borders, number formats are all dropped (paste only sets value/number/string via build_set_op); No relative reference adjustment on paste (Excel shifts =A1 by the paste offset); combined with value-only copy this makes formula copy unusable | Add an internal clipboard model that captures value+formula(+shifted refs)+style for a copied range, plus a matching rich (HTML/TSV) OS payload; make paste prefer the internal model (formulas + formats) and fall back to TSV parsing for external text; shift relative refs by the paste delta. |
| **Cut** | 🟡 Partial | ★ | Cut exists only as a context-menu item and is implemented as copy-then-immediately-clear-source. There is no Ctrl+X shortcut, no marching-ants cut indicator, and no move-on-paste semantics (Excel clears the source only when the cut is pasted, preserving formulas/refs as a move). | No Ctrl+X keyboard shortcut at all (Ctrl+C and Ctrl+V exist at editor.js:1850-1851 but X is absent); Cut clears the source the instant you invoke it, not on paste — so if you never paste you have destroyed data, and the paste is just a normal (value-only) paste; No marching-ants / dashed cut-source outline to show what is pending | Implement true cut as a pending-move state (mark source, marching ants, Ctrl+X binding); on paste, move value+formula+format and clear the source with reference-rewrite so formulas that pointed at the moved cells follow. |
| **Paste special** | ⬜ Missing | — | No paste-special of any kind: no values-only, formats-only, formulas-only, transpose, paste-with-operation (add/subtract/multiply/divide), column-widths, or paste-link. Both Excel and Sheets ship a full paste-special menu (Ctrl+Shift+V / Ctrl+Alt+V). | No Ctrl+Shift+V or paste-special submenu anywhere in the toolbar or context menu; No transpose, no values-only paste (the most-used paste-special mode); No paste-with-operation and no paste column widths / paste formats-only | Once the internal rich clipboard exists, add a paste-special menu (Ctrl+Shift+V) with values-only, formats-only, formulas-only, transpose, and arithmetic paste operations. |
| **Drag-fill / autofill** | 🟡 Partial | ★★ | Fill only TILES/repeats the source range (values + style) and shifts relative formula refs. There is NO series detection: no numeric progression (1,2,3->4,5,6), no date/time increment, no month/weekday text series, and no linear/growth trend. Also no double-click-to-autofill-down, no Ctrl+D/Ctrl+R, and no autofill-options popup. | No series continuation — dragging 1,2 fills 1,2,1,2 instead of 3,4; this is the defining autofill behavior and it is absent; No double-click on the fill handle to auto-fill down to the extent of adjacent data; No Ctrl+D (fill down) / Ctrl+R (fill right) keyboard shortcuts | Add a series engine (arithmetic step, date/month/weekday, linear & growth trend) chosen by the source pattern; add double-click autofill-down, Ctrl+D/Ctrl+R, and an autofill-options popup with copy-vs-series toggle. |
| **Undo / redo depth** | ✅ Done | ★★★ | Depth is effectively unlimited and each op is invertible — actually exceeds Excel's ~100-step cap. Gaps are ergonomic: no operation coalescing, no undo-history labels/tooltips, and multi-range formatting is recorded as several separate steps. | Multi-range (Ctrl+click) formatting runs fn per range in formatSel (editor.js:999-1002), so one bold action across 3 ranges is 3 undo steps instead of 1; No descriptive undo/redo tooltips or history dropdown (Excel shows 'Undo Typing', Sheets lists steps); No coalescing of rapid same-cell edits (each commit is its own step — usually fine, but a redesign-worthy detail) | Batch multi-range formatting into a single Batch op; add undo/redo tooltips with action labels; consider a soft cap or memory-aware trim on the history vectors. |
| **Find & replace** | 🟡 Partial | ★★ | Active-sheet-only substring search over display text with a case toggle and replace-all. Missing: replace-one (Replace next), match-entire-cell, regex/wildcards, search within formulas, all-sheets/workbook scope, scope-to-selection, and any highlight of all matches. Replace only rewrites string cells — numbers and formulas are never replaced. | No 'Replace' (single) button — only Replace all (html:246), so you cannot step-and-replace; Replace touches only SharedString/InlineString cells (lib.rs:326-331); text inside numbers and formulas is untouched, and find matches on computed display text so you can never find/replace the literal formula text (e.g. searching 'SUM'); No match-entire-cell and no regex/wildcard options (only a case toggle) | Add a Replace-next button and match-entire-cell + regex options; search over cell input (including formula text) and allow replacement in numbers/formulas; add all-sheets scope and paint a highlight over every match cell in draw(). |
| **Autocomplete of values** | ⬜ Missing | — | No autocomplete of cell VALUES: typing text does not suggest matching entries already present in the column, and there is no pick-from-list dropdown (Excel's Alt+Down / Sheets' column suggestions). Only formula function names autocomplete. | Typing a repeated text value in a column offers no completion from prior entries (the single biggest data-entry accelerator in Excel/Sheets); No Alt+Down 'choose from list of values in this column' dropdown; Function autocomplete (the one that exists) is keyed only to the inline editor, not the formula bar, and offers names only — no argument/signature tooltip once you are inside the parens | Add column-value autocomplete: as text is typed, suggest the longest matching prior value in the same column with inline ghost text (Tab/Enter to accept), plus an Alt+Down pick list of distinct column values. |
| **Delete / clear** | 🟡 Partial | ★★ | Delete/Backspace and 'Clear contents' both remove the ENTIRE cell (value AND style) because ClearCell maps to cells.remove(). Excel/Sheets Delete clears contents but KEEPS formatting, and offer separate Clear Formats / Clear All. There is no clear-formats-only and no clear-all command. | Delete key wipes formatting too — a formatted cell loses its fill/borders/number format on Delete, contradicting the 'Clear contents' label (editor.js:1585) and every reference product; No Clear Formats and no Clear All commands (only the one destructive clear); No clear-comments/clear-hyperlinks granularity (those features don't exist yet, but the clear menu has no room reserved) | Split clear into Clear Contents (keep style — replace value with Empty via SetValue, do not remove the cell), Clear Formats (reset style only), and Clear All; bind Delete to Clear Contents so formatting survives. |

## Formatting

| Feature | Status | UX | Parity gap vs Excel/Sheets | Top UX issues | Recommendation |
